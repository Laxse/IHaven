# 2026-10-13 工作日志

## 修复：窗口先调大再调小后左侧导航左移遮挡（IHaven Browse）
- 现象：用户反馈窗口 resize（先放大再缩小）后左侧 sidebar 被推到窗口左缘外、被裁剪遮挡。
- 根因两处：
  1. 布局：根 `VStack` 默认 center 对齐，中间 `HStack(sidebar+mainArea)` 无 `maxWidth`。一旦主区内容（masonry）在 resize 的某一帧宽度超出窗口宽，居中的 HStack 整体溢出，把左侧 sidebar 挤出窗口左缘被裁。
  2. 状态：旧 `MasonryView` 用 `@State width` + `onGeometryChange` 自反测量列宽，调大再调小时该值可能 stale 不回缩（列宽不跟随缩小）。
- 修复（`Sources/IHavenApp/Features/Browse/BrowseView.swift` + `BrowseGrid.swift`，提交 ed41d72）：
  - 根 `VStack(alignment:.leading)`；中间 HStack 显式 `.frame(maxWidth:.infinity,maxHeight:.infinity,alignment:.leading)`；sidebar 固定 `.frame(width:208)` 且先定宽后填高。sidebar 永远钉在 x=0，不再溢出。
  - `MasonryView` 改为 `GeometryReader` 直接测量可用宽度（每布局 pass 取真实值），移除 `@State` 反馈环，彻底消除 enlarge→shrink 的 stale 宽度。
- 验证：`swift build --disable-sandbox` 零错误零警告；三道门禁 convention/security/api 全 PASS；BrowseView 299 行（≤300 红线）。
- 待用户在 Xcode 复核（⌘Q→⌘B→⌘R，手动先放大再缩小复现验证）。

## 新增：开发期进程内 mock wallhaven 服务（免 VPN）
- 动机：wallhaven.cc 需 VPN，开发环境不便长期开；用户要求先写 mock 服务模拟请求。
- 方案（`Sources/IHavenApp/Infrastructure/Network/MockWallhaven.swift` + 改动 `WallhavenClient.swift`/`IHavenApp.swift`，提交 f607075）：
  - `MockWallhavenProtocol: URLProtocol` 拦截对 `mock.wallhaven.local` 的请求：
    - `/api/v1/search` 返回合成 `WallhavenPage` JSON（24 张/页，竖/方/横/宽/超宽五形态循环；分页 page>lastPage 返回空数据 mimics 真实）。
    - `/thumb/<id>`（缩略图）与 `/wallpaper/<id>`（原图）返回进程内 CoreGraphics+ImageIO 生成的渐变 JPEG。
  - `WallhavenEndpoint.search` 改为按 `IHAVEN_MOCK` 环境变量计算 base URL（读 `ProcessInfo`，无全局可变状态 → 满足 Swift 6 并发安全），默认仍指向真实服务。
  - `IHavenApp.bootstrap()` 开头调用 `MockWallhaven.configureIfNeeded()` 注册拦截协议。
  - 优势：整条链路（请求→JSON 解码→Nuke 预取→缩略图渲染→设为壁纸原图下载）零网络，且真实 `WallhavenClient` 逻辑完全复用、被实测。
- 启用：Xcode Edit Scheme → Run → Arguments → Environment Variables 加 `IHAVEN_MOCK = 1`；删除即切回真实服务。
- 验证：`swift build` 零错误零警告；convention/security/api 三道门禁 PASS。GUI（缩略图是否经 Nuke 走拦截协议）需用户在 Xcode 复核；若缩略图不加载，备选方案是给 Nuke `ImagePipeline` 的 `DataLoader` session 显式注入含该 protocol 的 config。
- 应团队需要，已在 `README.md` 新增「本地开发（免 VPN Mock）」一节（启用步骤 + 实现说明），提交 cfb6064。

## 修复：右侧图片区域无法滚动 + 无翻页功能
- 现象：用户反馈 resize 修复（ed41d72）后右侧图片区无法滚动，且整页只有第一页、无翻页。
- 根因两处：
  1. 无法滚动：上一轮为修 resize 把 `MasonryView` 从 `onGeometryChange` 测量版改成 `GeometryReader` 直接测量，但 `GeometryReader` 在 `ScrollView` 内会撑满无限高度、破坏 ScrollView 对内容高度的判定 → 滚动失效。布局对齐才是 resize 左移的真因，改 MasonryView 是过度改动，本轮撤销。
  2. 无翻页：`BrowseViewModel.nextPage()` 此前虽已定义但从没被调用接线，翻页逻辑悬空。
- 修复（提交 6973f28）：
  - `MasonryView` 还原为 `onGeometryChange(for:CGFloat.self)` 测量版（`.onGeometryChange` 作用在内容 VStack 上，不影响 ScrollView 滚动高度，规避 GeometryReader 的无限高度问题）。
  - `BrowseView.searchContent` 的 `ScrollView` 内底部加触底哨兵：加载更多行 `.frame(height:40).onAppear { Task { await viewModel.nextPage() } }`；内容变高后哨兵下移，避免重复触发。
  - `BrowseViewModel.nextPage()` 加 `loadingMore` 重入保护（`guard case .loaded, !loadingMore else {return}`；成功 append、失败回退 page 并置 failed）。
- 验证：`swift build --disable-sandbox` 零错误零警告；convention/security/api 三道门禁 PASS；BrowseView 通过压缩注释/内联函数压到 296 行（≤300）。
- 待用户 Xcode 复核：开 `IHAVEN_MOCK=1`，⌘B→⌘R，确认①右侧可滚动、下滑触底自动加载下一页、状态栏「已加载 N 张」递增；②Nuke 缩略图是否经拦截协议加载（mock 下若不显示，备选给 Nuke `ImagePipeline.DataLoader` session 注入含 `MockWallhavenProtocol` 的 config）。

## 修复：翻页只加载一页后卡在「加载更多…」（提交 c2987bf）
- 现象：用户截图反馈初始加载 48 张（=24×2）后一直显示「加载更多…」转圈、不再增页。
- 根因：无限滚动哨兵把 `.onAppear { nextPage() }` 挂在 **非惰性 `VStack`** 的子视图上。非惰性 VStack 在初始渲染时一次性建立全部子视图，`onAppear` 只触发一次 → 只加载了第 2 页（24→48）后再也不触发。`nextPage()` 的 `loadingMore` 重入保护本身没问题，是触发源只叫了一次。
- 修复：触发逻辑从 `onAppear` 移到 `ScrollView().onScrollGeometryChange`，用 `distance = contentSize.height - (contentOffset.y + containerSize.height)` 做确定性触底判定（`< 240pt` 预取下一页）。内容增长后 distance 自动变大，需再次滚动到接近底部才触发下一页；重入仍由 `ViewModel.loadingMore` 拦截。底部 HStack 退化为纯展示指示。
  - 为什么不用 LazyVStack+onAppear：onScrollGeometryChange 不依赖惰性渲染语义，判定确定、也能正确处理内容增长，更稳。
  - 部署目标 macOS 26.0，`ScrollGeometry`/`onScrollGeometryChange`（macOS 15+）可用。
- 验证：`swift build --disable-sandbox` 零错误零警告；convention/security/api 三道门禁全 PASS；BrowseView 298 行（≤300）。
- 待用户 Xcode 复核：下滑触底应逐页加载（24→48→72…），状态栏「已加载 N 张」递增，mock 下到第 10 页后停止（mock lastPage=10）。
