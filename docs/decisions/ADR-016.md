# ADR-016: 动态壁纸改为「静态图本地生成帧序列」，移除视频导入/播放

## Status: Accepted (2026-10-15)

## Background

原动态壁纸功能有两个并存的问题：

1. **功能不可用**——用户反馈「动态壁纸删也删不掉，一点进去就卡死」。根因在 `DynamicWallpaperEngine`：在 SwiftUI 按钮动作那一轮里**同步建桌面层窗口**会重入布局、在 autorelease pool drain 时 SIGSEGV（即「点一下就卡死 / 消失」）；此外 options 字典里 Swift 原生值未桥接 `NSNumber`，AppKit 一发 `integerValue` 即未捕获异常、进程直接终止。
2. **设计方向需要调整**——旧链路是「导入 MP4/MOV → `AVPlayer` + `AVPlayerLooper` 播放」。用户明确想要的是另一种形态：**导入一张静态壁纸，再用工具 / AI 生成一段动态壁纸**，而不是让用户自己去找视频文件。

把这两点合起来，正确做法不是修修补补旧播放器，而是**重设计整条链路**：删掉视频导入与播放，改为「导入静态图 → 本地一次渲染出帧序列 → 播放侧逐帧轮播」。AI 生视频作为增强项后置（用户在设置里填 Key 后才出现入口），本地离线优先。

## Decision

- **彻底移除视频链路**：`ImportedKind` 枚举删除 `.video` 仅留 `image` / `animation`；`AVMediaProbe` 不再依赖 `AVFoundation`、不再探测视频时长 / 接缝 / 海报，`unsupportedReason` 显式拒绝 mp4/mov/m4v/avi/mkv/webm/flv/wmv/3gp 与 gif，文案写明「动态壁纸已改为由静态图生成，不再导入视频文件」；`LocalImportService` 只导入静态图（`kind: .image`）；`Database` 的 `seamless` 列保留但不再写入；相关 UI（视频接缝提示 `SeamNoticeView`、导入摘要里的 `videoCount`）一并删除。
- **新增本地生成链路**：
  - `AnimationPreset`（breathe 呼吸 / pan 横移 / zoomIn Ken Burns 缓推 + 竖向微移）+ `AnimationSpec`（seconds 6~30、amplitude 0.04~0.24、frameCount）。
  - `AnimationRenderer`（CoreGraphics / ImageIO）：导入时**降采样**源图到长边 1920 以内（不整图解码），再按 `cropRect(at:in:outputAspect:)` 逐帧裁剪并写 `frame-%04d.jpg` 到 `<uuid>/` 目录。
  - `AnimationGeneratorView`（生成面板）：选源图、实时 `TimelineView` 预览（用与渲染同套仿射公式复现运动，不落盘）、`Picker` 选预设、滑块调时长 / 幅度，`generate()` 调 `library.generateAnimation`。
  - `LocalLibraryViewModel.generateAnimation(source:spec:)`：取主屏 aspect、`frameCount = max(24, Int(seconds*12))`，`Task.detached` 调渲染器，落库后置顶 `imported`。
- **播放改版**：`DynamicWallpaperEngine` 改为**帧序列轮播**——输入是帧目录而非视频；每帧仅把 JPEG 赋给 `NSImageView.image`，零解码队列、零合成。保留 ADR-015 的双层结构：静态层写首帧兜底（锁屏 / 切 Space 不闪回），动态层每屏一个 borderless 窗口 + Timer 逐帧替换，并修复上述两条崩溃约束（options 显式 `NSNumber`、建窗口延后一整轮、退出时 `willTerminate` 同步回收）。
- **无缝循环**：`cropRect` 三种预设都满足 `t=0` 与 `t=1` 返回同一构图（用 `(1 - cos(2πt))/2` 往复），循环时无跳变。

## Rationale

### 一、为什么是「帧序列轮播」而不是继续用 `AVPlayer` 播 MP4

旧版用 `AVPlayer` 播放视频，需要解码器、播放器生命周期、循环器（`AVPlayerLooper`），且用户必须自备视频。新形态是**本地一次性把运动烘焙进 JPEG 帧**，播放侧退化成「定时器换图」——没有解码器、没有音频轨道、没有播放器状态机。慢速运动（呼吸 / 横移 / Ken Burns 都是秒级缓动）下 12fps 足够，磁盘换复杂度是划算的。`/tmp/rendertest` 独立验证：三预设各渲染 24 帧，输出尺寸匹配主屏比例（拉伸不变形）、首末帧之外帧间确有像素差异，验证通过。

### 二、为什么本地优先、AI 后置

用户设想里 AI 是「生成工具之一」，但并非离线必备。先做本地生成能保证**不联网、不填 Key、不依赖第三方 API 也能用**；AI 生视频作为「设置里填 Key → 出现入口」的增强项，是叠加而非前置依赖，符合「轻量免服务器」的总体取向。

### 三、为什么三种预设而非单一

呼吸 / 横移 / 缓推覆盖「不平移」「只平移」「平移 + 缩放」三种读感，给用户区分度，且三者都能用同一个 `cos` 往复公式保证无缝，实现成本几乎为零，不需要为每个预设写特例。

### 四、为什么降采样到 1920 而非原图

arch §6.2.2 的意图是「不整图解码 8K 原图」。1920 覆盖绝大多数显示器 @1x；@2x 屏由窗口层再放大一次，慢速运动下软化不可见，而磁盘与生成时间差一倍（帧面积差 4 倍）。

## Consequences

### 正面

- 动态壁纸不再依赖用户自备视频，导入即一张静态图即可。
- 播放侧零解码零合成，去掉了 `AVPlayer` 整条生命周期与崩溃面；原「卡死 / 消失」根因被新引擎彻底规避。
- 无缝循环无跳变，体验比「视频硬循环」更顺。
- 离线可用，不消耗任何外部配额。

### 负面

- 磁盘占用：一段 12s / 144 帧 @1920×1080 约数十 MB，比单张静态图大；需在「设置」里给出清理入口（已留 `AppPaths.animations` 目录语义，待补 UI）。
- 运动形态有限：仅三种预设，不能做粒子 / 形变等复杂效果；复杂效果走后续 AI 生视频增强。
- 帧序列是预渲染产物，修改时长 / 幅度需要重新生成，不能实时调参后即时生效（生成面板的 `TimelineView` 预览弥补了这部分交互）。

## Alternatives Considered

**保留 `AVPlayer` 播放用户导入的视频。** 既不符合「导入静态图生成」的新形态，又背着旧崩溃面与解码复杂度。否决。

**本地生成 GIF 而非 JPEG 帧序列。** GIF 256 色调色板在渐变天空 / 肤色上明显断层，且 GIF 解码在连续播放下仍是逐帧 raster，并不比 NSImageView 换图更省；JPEG 帧序列无损观感、单帧随机访问、易清理。否决。

**本地用 `AVAssetWriter` 把运动烘焙成 MP4 再播。** 绕回 `AVPlayer` 复杂度，且多一道编码；既然播放侧已退化成换图，就没必要再引入编解码器。否决。

**AI 生视频作为唯一入口（纯云端）。** 离线不可用、需 Key、依赖第三方稳定性，违背「本地优先、轻量免服务器」。否决，改为后置增强。
