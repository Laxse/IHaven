# ADR-008: 不集成 FFmpeg，不依赖私有 API

## Status: Accepted (2026-10-08)

## Background

IHaven 的动态壁纸需处理 GIF / WEBM / MP4（PRD F9）。其中 WEBM/VP8/VP9 在 macOS 上**无原生解码支持**——AVFoundation 不支持 Matroska/WebM 容器，Safari 之外的 WebKit 不内置这些 codec。

团队要求评估所有可行技术路径。同时存在一条诱惑性路径：`WallpaperExtensionKit` 私有框架可实现系统级动态壁纸，社区已有 macOS 26 的可用实现。

## Decision

1. **不集成 FFmpeg**。WEBM/MKV 播放明确不支持，给出明确原因，不静默黑屏。
2. **不依赖 `WallpaperExtensionKit` 或任何私有 API**。MVP 与 V2 严禁依赖；V3 若评估，必须设计降级路径。
3. **不实现 HTML/CSS/JS 壁纸**（与 PRD Out-of-Scope 一致）。

## Rationale

### 为何不集成 FFmpeg

支持一个格式的代价：

| 代价 | 说明 |
| --- | --- |
| 二进制体积 | 静态链接 FFmpeg 增长数十 MB，与「Apple 官方级品质」的安装体验冲突 |
| 许可证合规 | LGPL/GPL 边界复杂，静态链接需法务确认。商业产品在此出错代价极高 |
| 供应链风险 | 引入一个体量大、更新频繁、历史上多次出现高危 CVE 的 C 依赖 |
| 长期维护 | FFmpeg API 频繁变更，需持续跟进 |

而收益是：多支持一个 WebM 格式。

**权衡结论**：PRD 的核心主张是「可测量可控的功耗」与「Apple 官方级品质」。为支持一个格式引入上述代价，与产品定位负相关。

**明确的用户沟通**：遇到 WEBM 时告知「macOS 系统不支持该格式的硬件解码」，并提供「转换为 MP4」的引导，而不是静默失败或偷偷转码。

### 为何不依赖私有 API

`WallpaperExtensionKit` 需通过 `dlopen` 加载 + Mirror 反射调用其 XPC 类型。风险：

1. **Apple 可在任一系统版本移除或更改**——这不是理论风险，是 App Store 审核与系统更新的常态行为
2. **崩溃风险不可控**——私有框架结构变化会直接导致进程崩溃，而动态壁纸进程崩溃会让用户桌面变黑
3. **私有 API 是 App Store 拒审理由**——虽 MVP 为自分发，但产品定位为商业化，长期必须过审
4. **社区实现仅验证 macOS 26 与 27 beta**——未在正式版充分验证

PRD F12（锁屏动态壁纸）已标注此风险并排入 V3 末位，架构师认同。

**V3 若评估此项的硬约束**：必须设计降级路径（私有 API 不可用时回退到应用内独立渲染层，即 ADR-003 的窗口方案），且必须把私有框架调用集中在**单一隔离模块**内，便于不可用时整体切除。

### 为何不实现 HTML/CSS/JS 壁纸

每个网页壁纸需一个浏览器内核渲染进程（约 300MB/进程级）。与「可测量可控的功耗」核心主张**直接冲突**。PRD 已明确否决，本 ADR 确认该结论。

## Consequences

### 正面

- 供应链与许可证风险最小化
- 安装体积可控
- 无因私有框架变化导致的不可控崩溃
- 功耗承诺可兑现（硬件解码路径，Apple Silicon 有专用解码单元）

### 负面

- **明确放弃 WEBM/MKV 播放能力**。若用户素材主要是 WebM，产品价值受损。需在产品内明确沟通
- 用户需自行转换格式，提供引导而非代劳
- V3 的锁屏动态壁纸（PRD F12）受此约束，可能最终无法实现

### 关键约束（实现规范）

1. **格式探测前置**。导入壁纸时用 `AVURLAsset` 探测可加载性，不兼容格式立即提示，不进入后续流程
2. **错误信息必须具体**。「macOS 不支持 WEBM 的硬件解码，建议转换为 MP4」优于「加载失败」
3. **GIF 的 CPU 特性需实测**。GIF 长时间播放 CPU 占用可能显著高于硬解视频，需按帧数/尺寸降级为静帧
4. **禁止在生产代码中出现任何 `dlopen` 私有符号加载**。CI 静态检查拦截

## Alternatives Considered

**集成 FFmpeg**：体积、许可证、供应链三重代价，换一个格式。否决。

**`WallpaperExtensionKit` 私有框架**：不可控的崩溃与拒审风险。MVP/V2 严禁；V3 需隔离与降级路径。否决（现阶段）。

**WKWebView 播 WEBM**：功耗不可控（约 300MB/进程），与核心主张冲突。否决。

**QLVideo 类第三方框架**：等价于集成 FFmpeg，且引入第三方 QuickLook 扩展，稳定性不可控。否决。
