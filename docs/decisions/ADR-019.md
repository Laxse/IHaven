# ADR-019: AI 图生视频作为动态壁纸的可选帧来源（Plan B）

## Status: Accepted (2026-10-18)

## Background

ADR-016 把动态壁纸定为「静态图 → 本地渲染 JPEG 帧序列 → 桌面层窗口逐帧播」，刻意**不接云端**：
零成本、离线、CPU 可控、无缝循环。代价是只能对静图做 Ken Burns 式运镜，做不了「真·画面运动」。
`AnimationGeneratorView` 的注释里因此预留了一句「AI 生视频作为后续可选项（设置里填 Key 后启用）」。

用户要补上这个可选项，且明确要「主流」的那种——即 AI **生成会动的画面**（图生视频），
而不是「AI 画张图再运镜」。但这里有个张力：主流动态壁纸靠**视频播放**，而 ADR-016 的引擎只播帧。

## Decision

新增 **AI 图生视频**作为动态壁纸的**可选帧来源**，与「本地渲静图」并列，**不推翻 ADR-016 的播放引擎**。

1. **管线**：选一张本地静态图 + 运动描述 → 调 AI 图生视频 API（用户自备 Key）拿 MP4 →
   **AVFoundation 抽帧**成 `frame-%04d.jpg` → 落 `Animations/<uuid>/` → 现有 `DynamicWallpaperEngine` 照播。
   引擎、帧存储、性能护栏、循环语义全部复用，一行不改。

2. **为什么抽帧而非给引擎加视频播放（即不改 ADR-016）**：给桌面层窗口加 `AVPlayer` 是最主流，
   但会把 ADR-016 否决的一整包问题请回来——codec 兼容、CPU/解码占用、视频资产管理、循环接缝。
   抽帧方案让「帧来源」可插拔（本地渲静图 / AI 视频抽帧），播放侧保持单一、轻、可控。
   AVFoundation 原生解 H.264/HEVC，**不捆 FFmpeg**（Non-goals 守住）。

3. **协议分层**：`AIVideoGenerating` + `VideoFrameExtracting` 两个 Core 协议；实装在
   Infrastructure（`ReplicateVideoClient`）与 Platform（`AVFoundationFrameExtractor`）。
   Feature 只见协议；具体提供商可换（再写一个 `AIVideoGenerating` 实现、装配点换一行）。

4. **成本护栏（硬要求）**：每一次生成花用户 Key 的真金白银。故——每次生成前一次确认弹窗；
   设置页明示「会计费 / 需自备 Key / 需能访问服务商网络 / 内容合规自负」；客户端绝不自动重试连打。

5. **Key 独立存储**：`~/.ihaven/ai-key`（ADR-010 同机制、`0600`、不进 git/日志），与 wallhaven Key
   分文件、单例共享（设置面板写 / 客户端读同一实例，避免内存缓存漂移）。

## Rationale

- **为什么是图生视频而不是文生图**：用户要的是「会动的画面」。文生图 + 运镜仍是静图的错觉，
  达不到「主流 AI 动态壁纸」的预期。图生视频给的是真实运动。
- **为什么不视频播放**：见 Decision 2——用「换帧来源」绕开「换播放内核」，以最小架构改动拿到
  主流观感，同时不牺牲 ADR-016 立下的轻量 / 可控 / 无缝。
- **成本为何要单独成条**：这是本 App 第一个「花用户钱」的功能。默认开启的静默计费是不可接受的，
  所以确认弹窗 + 明示边界是功能的一部分，不是附加说明。

## 已知限制 / 待首验

- **Replicate 端点与模型未真机验证**（无 Key、付费）：`model` 常量与 `input` 字段名以官方文档为准，
  不同图生视频模型 schema 有差异，需首次用真 Key 跑通后核对（同当初 wallhaven 端点要实测一遍）。
- **循环接缝**：AI 视频片段通常不为无缝循环设计，循环点可能跳。可在抽帧后做「正放 + 倒放」的
  ping-pong 缓解（后续，未做）。
- **输入格式**：底图统一转 ≤1024 长边 JPEG 再上传（模型可靠吃 JPEG 且减小请求体）；源库的
  HEIC/WebP 由这一步归一，不依赖模型原生支持。
- 输出分辨率即 AI 视频分辨率（抽帧时长边 ≤1920），非严格等于屏幕比例；铺放由系统按当前填充模式处理。

## 关联

- 依赖/不改：ADR-016（播放引擎）、ADR-015（本地库 / `kind` 分类，AI 产物落 `kind: .animation`）。
- 明确不做：free-form 裁剪比例（ADR-018 已否决）、视频播放内核（本 ADR 决定不改）。
