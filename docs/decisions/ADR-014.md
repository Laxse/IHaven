# ADR-014: 详情页以 overlay 盖在主区上，不用 `if/else` 换页

## Status: Accepted (2026-10-15)

## Background

用户反馈「详情页返回的时候，滚动条位置没保留，到顶上了」。

`BrowseView.mainArea` 原先用 `if let detail { detailPage(detail) } else { 主内容 }` 二选一：进入详情时主内容那一支**从视图树上被摘掉**，`detail = nil` 返回时新建一棵。而 SwiftUI 的 `ScrollView` 不持有跨生命周期的偏移——新实例偏移恒为 0，于是无论之前滚到第几屏，返回后都回到顶部。

这不是「忘了记录偏移量」这类遗漏，而是**换页模型本身的副产品**：只要详情页是通过替换主内容实现的，被替换掉的 `ScrollView` 状态就无从保留。

## Decision

`mainArea` 改为常驻主内容 + `.overlay { if let detail { detailPage(detail) } }`。详情页自始至终是**盖在主区上的一层**，不替换底下的任何东西。

## Rationale

### 一、不销毁就不需要恢复

保留滚动位置有两条路：记下偏移再设回去，或者**让那个 `ScrollView` 根本不消失**。后者不需要引入任何状态，也不需要和 masonry 的自定义布局打交道——`MasonryView` 是手写的分列布局，没有 `scrollTargetLayout()` 可挂，靠 `ScrollViewReader` + 锚点 item 回滚只能近似到「某个 item 的顶部」，滚到一半的位置回不去。overlay 是精确解：底层视图自始至终是同一个实例，偏移原样保留。

### 二、视觉与行为等价，没有引入新的交互差异

详情页是不透明整块（`.background(IHaven.Color.bg)` + `.frame(maxWidth/maxHeight: .infinity)`），完全遮住主区，观感上与「换了页」一致；工具栏、侧栏、状态栏都在 `mainArea` 之外，改动前后一样不受影响。底层 `ScrollView` 被完全覆盖，收不到滚动与点击事件，不存在「看得到详情页却滚得动底下列表」的问题。

### 三、顺带保住了另几处同类状态

同一个 `mainArea` 子树里除了滚动偏移，还有「已设置」页与收藏页各自的布局状态。换页模型下这些一起丢；overlay 模型下一起保住。这不是附带收益的巧合——它们是同一个根因的同一批受害者。

## Consequences

### 正面

- 详情页返回后瀑布流停在原处，无额外状态、无近似误差。
- 主区子树在详情展示期间保持存活，其布局状态（收藏页 / 已设置页）同样保留。
- 删除了 `if/else` 两支里重复的背景与 frame 修饰，代码更短。

### 负面

- 底层 `ScrollView` 在详情展示期间仍然存活并占据视图树，内存占用略高于换页模型（瀑布流是普通 `VStack` 而非 `LazyVStack`，已在树上的卡片不会被回收）。当前页 24–48 张卡的量级下可接受；若将来改成无限滚动且单页数百张，需要重新评估（届时的正解是 `LazyVStack`，而不是退回换页）。
- 详情页展示期间底层的内容更新（如触底加载下一页）照常发生，`onScrollGeometryChange` 的触底判定仍会命中既有阈值，与改动前行为一致。
- 「返回」在语义上不再是一次页面替换：若将来要加入前进栈或转场动画，需要改为显式导航容器，而不是在 overlay 上叠加。

## Alternatives Considered

**记录滚动偏移并在返回时设回。** SwiftUI 没有公开的可写偏移 API（`UIScrollView` 的 `contentOffset` 在 macOS 上无对应物），只能靠 `ScrollViewReader.scrollTo(_:anchor:)` 回滚到某个 item —— 而 masonry 是自定义分列布局，没有 `scrollTargetLayout()`，且 `scrollTo` 只能对齐到 item 边界，滚到一半的位置必然跳位。否决。

**给 `ScrollView` 加 `.id(stableID)` 稳定身份。** SwiftUI 的身份稳定只保证视图不被重建，不保证 `ScrollView` 内部偏移被持久化；`if/else` 分支切换时整支被移除，身份信息随之消失。否决。

**把详情页做成 `.sheet` / `NavigationStack`。** `.sheet` 是独立窗口层，会带自己的关闭动画与窗口尺寸约束，且同样不解决底层滚动位置（sheet 关闭后底层本就在，这条其实可行）——但 sheet 的呈现形态（居中卡片 / 可拖拽关闭）与线稿要求的「主区内二级页面」不符。`NavigationStack` 需要重构整个主窗口导航模型，超出本次范围。均不采用。
