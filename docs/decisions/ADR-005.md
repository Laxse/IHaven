# ADR-005: 图标库锁定 SF Symbols

## Status: Accepted (2026-10-08)

## Background

团队 P0 绝对规则要求：Spec 与架构文档中禁止使用 emoji 作为功能图标；技术栈选型必须锁定一套图标库，全项目统一不混用；由架构师按项目技术栈选型。

team-lead 给出倾向：macOS 优先 SF Symbols（系统原生、无需依赖、macOS 11+ 全覆盖），除非有充分理由反对。

本 ADR 锁定该选型并给出可执行规则。

## Decision

全项目功能图标统一使用 **SF Symbols**。禁止 emoji 作为功能图标，禁止混入任何其他图标库或自建图标集。

## Rationale

| 候选 | 评估 |
| --- | --- |
| **SF Symbols** | 系统原生、零依赖、macOS 11+ 全覆盖（本项目目标 macOS 26，余量充足）、自动适配浅色/深色与辅助功能设置、macOS 26 下有 Tahoe 风格变体 |
| 自带 SVG 资源包 | 需手工维护上千图标、需自建深色变体、bundle 体积膨胀、无法跟随系统语义 |
| Lucide / Heroicons | 面向 Web 的 24px 网格与 stroke 风格，与 macOS 26 视觉语言不匹配 |
| emoji 作为功能图标 | P0 规则禁止 |

### 为何反对「品牌化图标」这条反对意见

可能的反对意见是：SF Symbols 样式单一，不足以承载品牌辨识度。

反驳：PRD 明确「Apple 官方级品质」定位，SF Symbols 是与该定位唯一一致的选择——它就是 Apple 自己应用所用的图标体系。引入外来图标风格反而会削弱而非增强该定位。

若未来确需品牌化元素，正确做法是作为**独立资源包叠加**（如空白态插画、空状态图形），而非替换系统功能图标体系。这样既保留品牌辨识度，又不破坏系统一致性。

## Consequences

### 正面

- 零依赖，供应链面最小
- 自动适配深色模式与 macOS 26 Liquid Glass 视觉语言
- SF Symbols 应用无需图片资源，bundle 不膨胀
- 可访问性自动获得（系统符号带语义标注）

### 负面

- 视觉风格由系统决定，无法完全自定义
- 极细的品牌化表达无法实现

### 关键约束（实现规范）

1. SwiftUI 中使用 `Image(systemName: "…")`，**禁止** `Image("…")` 指向功能图标资源
2. 使用 `.symbolRenderingMode()` 明确层级（`.hierarchical` 用于次要图标，`.monochrome` 配合 `tint`）
3. 图标尺寸走 SF Symbols 的 `.imageScale` 语义，不硬编码像素
4. **AppIcon（应用图标）由设计侧用 Icon Composer 制作**，属独立资产，不受本规则约束
5. 架构文档与 Spec 中描述图标时写 SF Symbols 的 symbol name（如 `photo.on.rectangle.angled`），**不写 emoji**

## Alternatives Considered

**自带 SVG 图标库**：需维护 + 深色变体 + 体积膨胀，否决。
**Lucide / Heroicons**：Web 视觉语言与 macOS 26 不匹配，否决。
**emoji**：P0 规则禁止，否决。
